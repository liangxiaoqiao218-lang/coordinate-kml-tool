# Coordinate Three-Case RC R3 Pre-Commit Evidence

## Scope

R3 is a new, single-use RC window for the same three frozen images and the same `qwen3.8-flash` candidate. It does not reopen Run04, R1 or R2. It adds only:

- fresh R3 run/batch/database binding;
- a private, atomic, SHA-256-verified validated-result artifact;
- the diagnostic booleans and fixed codes needed to distinguish source context, UTM50S evidence, X/Y evidence, controlled hint handling and preflight/route failure;
- offline regression coverage for those newly modified boundaries.

It does not authorize or implement a Production change, model retry, fallback, direct OCR call, extra client execution, model substitution, PDF upload, reverse KML import, UI redesign, model-comparison administration or map-provider migration.

## Reused evidence

The previously accepted client preflight (`6/6`), admission (`30/30`) and isolated candidate (`33/33`) evidence is reused and was not rerun. R1 and R2 failure evidence remains retained. The result-artifact regression was completed at `11/11 PASS` before the R3-only identity rebinding and is reused because no artifact behavior changed during that rebinding.

All reused evidence is offline or mock evidence. It is not a real model result, browser Map result, KML download or Production proof.

## New R3 evidence

`scripts/coordinate-three-case-rc-r3-binding-regression.js` checks only the newly changed R3 boundaries:

- manifest bytes and admission digest match;
- manifest, admission, client and migration use the exact R3 identity;
- exactly three frozen cases are inserted;
- the 30-minute, three-dispatch, single-concurrency contract remains fixed;
- no replacement budget pool is created;
- Indonesia uses the existing six-call/CNY 5 ledger and MGRS/BFTM use the existing CNY 2 ledger;
- R1 and R2 remain closed and are not rewritten;
- four budget-bound RPCs remain `SECURITY DEFINER` with empty search path and service-role-only execution;
- exact model, one-call, zero-retry and zero-direct-OCR semantics remain fixed;
- the client preserves true Provider call observations and writes the private verified result artifact.

This suite performs zero HTTP and Provider calls.

```ini
COMMAND=node scripts/coordinate-three-case-rc-r3-binding-regression.js
EVIDENCE_CLASS=OFFLINE_STATIC_NO_NETWORK
RESULT=12/12 PASS
PROVIDER_CALLS=0
HTTP_REQUESTS=0
```

## Runtime boundary

The R3 database migration may create an `ARMED` run only. Activation remains a separate, single enable-deployment action after the visible client is waiting at its masked password prompt and the user has confirmed the window is operable. The single client execution must close the run, and the single disable deployment must follow regardless of terminal outcome. No RC or model execution is part of this pre-commit evidence.

## Result handoff boundary

The retained result artifact preserves finalized normalized geometry, source/final CRS, result identity/revision/hash, readiness/review state, fixed diagnostics and bounded Provider accounting. It omits credentials, tokens, headers, request bodies, raw Provider responses/text, source candidates and image payloads.

Retained result identity is not durable authorization for a later browser session. A real Map/KML browser qualification must use the same live/current identity or receive separate authorization. Offline artifact integrity is not a browser download proof and is not full-site recovery evidence.
